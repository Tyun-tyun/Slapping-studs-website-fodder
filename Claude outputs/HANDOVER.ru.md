# ТЗ для нового окна — сайт Slapping Studs

## Контекст

Прототип сайта студенческого хоккейного клуба SIJHV The Slapping Studs (Энсхеде, основан в 1982).
Чистые HTML + CSS + JS: ни фреймворка, ни сборки, ни зависимостей. Каждая страница — свой `.html`,
шапка и подвал скопированы в каждый файл одинаково. Контент живёт в `js/data.js` и правится прямо
в браузере через админ-консоль (хранится в localStorage). Бэкенда нет: формы никуда не отправляются.

- **Ветка:** `redesign/anti-slop`. **Ничего не закоммичено.**
- **Копия до всех правок:** `C:\Users\tyunk\Desktop\slapping-studs-backup-2026-10-30` — не трогать.
- **Запуск:** открыть `index.html` с диска либо поднять любой статический сервер в корне.

## Правила оформления, которым следует сайт

Сложились из разбора 247 сайтов-образцов; проверяются скриптом-инспектором.

- **Два шрифта.** Archivo — всё. «NY Rangers» (`/fonts`) — только вордмарк на главной и номера на джерси.
- **Запрещено:** моноширинный шрифт, мелкие подписи капсом с разрядкой, надписи-ярлыки над заголовками,
  нумерация «01 / 02 / 03», тонкие линии-разделители и рамки в 1px, градиенты (кроме затемнения на фото),
  тени у неподвижных элементов, стекло и размытие фона, ряды одинаковых карточек с иконками, эмодзи.
- **Разделять** тоном или воздухом, а не линиями.
- **Заголовки** максимум в две строки при 1440 / 768 / 390px. У каждой страницы один видимый `h1`.
- **Текст** 16–20px в полном цвете, ничего мельче 13px. Поля слева и справа равны.
- **Цвета** только из `css/tokens.css`: `--ink` #111417, `--ink2`, `--bone` #EDEAE1, `--gold` #F7C325.
  Золото — акцент, не заливка.
- **Личный кабинет и админка — экраны приложения,** у них правила мягче: рамки 1px и линии в таблицах
  разрешены, цвет только на данных и статусах, заголовок 18–28px, цифры с `tabular-nums`.
- **Найденные фотографии** всегда с подписью, что на них, и с указанием автора (`<span class="phcredit">`);
  никогда не выдаются за фото клуба. Лицензии в `assets/credits.json`.
- **Ничего не выдумывать:** нет отзывов, прессы, спонсоров и статистики, которых у клуба нет.
  Примерные данные помечаются и выносятся в отчёт.

## Проверка работы

```bash
node "<skill>/scripts/inspect.mjs" <страница.html> --out <папка>
```

Открывает страницу в настоящем браузере при 1440, 768 и 390px, меряет вёрстку и складывает скриншоты.
Для экранов приложения (`account.html`, `admin.html`) добавить флаг `--app`.
`<skill>` — папка скила `design-taste-frontend`.

**Скриншоты обязательно открывать и смотреть глазами** — инспектор ловит измеримое, но не уродство.

Срабатывания, которые можно игнорировать: `reduced-hidden` со списком «The association / History / 1982– / News»
(это скрытые пункты выпадающего меню), `palette-cream` (фирменный цвет bone), `no-footage`, `size-count`.

### 2. Технический долг в общих файлах (нашли субагенты, не чинили)

1. **`css/layout.css`** — голые селекторы `header{position:fixed}` и `footer{…}`. Любой семантический
   `<header>`/`<footer>` внутри страницы ломается: уезжает в x=0. Ограничить до `body > header` и `.sitefoot`.
2. **`.feedgrid`** — базовое правило в `components.css:282` объявлено после `@media (max-width:980px)`
   в `layout.css:123`, поэтому боковой рельс не схлопывается на телефоне. На `news.html` стоит заплатка
   в стилях страницы. Перенести медиазапрос в `components.css` ниже базового правила. То же касается
   `.chapgrid` и `.adgrid` — тот же блок, та же проблема.
3. **`js/views.js`, `postHTML()`** — выводит `.pmeta` (дата · тег · автор) до заголовка, из-за чего строка
   читается как запрещённый ярлык над заголовком. Переставить: сначала `<h3 class="pheadline">`, потом
   `.pmeta`, потом `.pex`. Сейчас обойдено через `order` в стилях страницы.
4. **`css/components.css`** — `.pex` 14.5px (ниже порога 16px) и `.pmeta` контраст 3.3:1. Поднять до 17px
   и `#4C5862` / `#6B5200`. Сейчас переопределено только на странице новостей.
5. **`js/views.js`, `postHTML()`** — у пустых фото-слотов подпись «Photo»; лучше `ph("news:"+n.id, …, n.title)`,
   чтобы подпись называла, что за снимок там должен быть.

### 7. Чего на сайте нет вообще

Описание модели прав для бэкенда уже есть в `js/auth.js` — этот файл задумывался как спецификация.
